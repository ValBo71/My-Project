# AI QA Assistant

**AI QA Assistant** е съвременно уеб приложение, създадено да автоматизира рутинните процеси в работата на QA инженерите. То използва Gemini AI за генериране на структурирани тест кейсове, откриване на неочевидни гранични случаи (edge cases), съставяне на сценарии за API тестване, генериране на автоматизационни скелети с Playwright и форматиране на сурови описания на дефекти в детайлни Bug репорти.

Проектът е проектиран с чиста архитектура (Clean Architecture / DDD-Lite) на бекенда и модерен, бърз и визуален интерфейс с React на фронтенда.

---

## Технологичен стек

### Бекенд (Backend)
- **C# & .NET 9**
- **ASP.NET Core Web API** (RESTful endpoints, Dependency Injection)
- **Entity Framework Core & SQLite** (одит и история на заявките в локална база данни)
- **Google Gemini API Integration** (HttpClient с native JSON response support)
- **DocX (Xceed)** (генериране и стилизиране на Word документи)

### Фронтенд (Frontend)
- **React & TypeScript** (Vite като бундлър)
- **Vanilla CSS** (модерна тъмна тема с градиенти, неонови акценти и Glassmorphic ефекти)
- **Lucide React** (набор от векторни икони за премиум усещане)

### Тестове (Testing)
- **NUnit 3** (тестване на бизнес логиката, парсерите и експорта)
- **Playwright for .NET** (E2E тестване на потребителския интерфейс в реални браузъри)

## Архитектура на проекта

Проектът е разделен на отделни слоеве съгласно принципите на **Clean Architecture**, което гарантира лесна поддръжка, тестваемост и слаба свързаност:

```text
src/
  ├── AIQAAssistant.Domain/         # Независим слой. Съдържа Enums и базови субекти (Entities) като HistoryRecord.
  ├── AIQAAssistant.Application/    # Съдържа DTOs, interfaces (AI client, DB, Export) и логика за промптове/парсване.
  ├── AIQAAssistant.Infrastructure/ # Имплементация на бази данни (EF SQLite), Gemini API интеграция и форматиране за експорт.
  └── AIQAAssistant.Api/            # Ендпоинти, Middleware за грешки, CORS настройки и DI конфигуриране.
```

## Настройка и конфигуриране

### 1. Настройка на Gemini API Ключ

За да функционира приложението, е необходимо да имате активен API ключ от Google AI Studio (Gemini). Ключът се чете по два начина (с приоритет на променливите на средата):

#### Опция А: Чрез системна променлива (Environment Variable)
Във вашия терминал (PowerShell за Windows) изпълнете:
```powershell
$env:GEMINI_API_KEY="your-api-key-here"
```

#### Опция Б: Чрез `appsettings.json`
Отворете [appsettings.json](file:///src/AIQAAssistant.Api/appsettings.json) и попълнете полето:
```json
"Gemini": {
  "ApiKey": "your-api-key-here",
  "Model": "gemini-2.5-flash"
}
```

## Стартиране на приложението

### 1. Стартиране на Бекенда (Web API)
Базата данни SQLite се създава автоматично при стартиране, така че няма нужда да пускате миграции ръчно.
```bash
cd src/AIQAAssistant.Api
dotnet run
```
Бекендът ще се стартира на адрес: `http://localhost:5131` (и HTTPS `https://localhost:7154`).

### 2. Стартиране на Фронтенда (React SPA)
Отворете нов терминал и изпълнете:
```bash
cd src/AIQAAssistant.Web
npm install
npm run dev
```
Фронтендът ще се стартира на адрес: `http://localhost:5173`.

## Тестване

### 1. Стартиране на Unit Тестовете (Бекенд)
В проекта има написани unit тестове, които тестват Gemini интеграцията, форматирането на промптове, парсването на JSON и експорт услугите.
За да ги стартирате:
```bash
dotnet test
```

### 2. Стартиране на E2E Тестовете (Playwright)
За да стартирате E2E тестовете, първо се уверете, че имате инсталирани браузърите на Playwright на вашата машина:
```bash
# Изпълнява се еднократно за инсталация на браузъри
dotnet build
pwsh tests/AIQAAssistant.E2E.Tests/bin/Debug/net9.0/playwright.ps1 install
```
След това стартирайте тестовете (уверете се, че фронтендът работи на порт `5173`):
```bash
dotnet test --filter FullyQualifiedName~AIQAAssistant.E2E.Tests
```

## Функционалности и примерни потоци

1. **Генериране на Тест Кейсове**: Въведете изискване (напр. *"User story за регистрация на потребител с имейл"*). Системата изпраща промпт, принуждаващ Gemini да отговори в структуриран JSON, който се парсва и се визуализира в карти с приоритети, предварителни условия, стъпки и тестови данни.
2. **Генериране на Edge Cases**: Анализира изискването и извежда скрити рискове, гранични стойности и технически сценарии, които често биват пропуснати в изискванията.
3. **Генериране на API Сценарии**: Въведете endpoint (напр. `POST /api/users`) и payload. Gemini ще разпише таблица със сценарии за валидация на схемата, липсващи полета, SQL инжекции и очаквани статус кодове.
4. **Automation Skeleton**: Генерира код по модела **Page Object Model (POM)** за Playwright на C#. Селекторите се изнасят в отделен JSON обект, което прави кода лесен за поддръжка.
5. **Bug Report Formatter**: Напишете кратко описание (напр. *"Файл над 10MB хвърля 500"*). Gemini ще го структурира в подробен QA Bug Report с препоръчителни допълнителни тестове и вероятна техническа причина за дефекта.
6. **Експорт на Резултати**: Всеки генериран резултат или запис от историята може да се изтегли локално в следните формати:
   - **JSON** (суров структуриран вид)
   - **Markdown** (за качване в GitHub/GitLab или Wiki)
   - **CSV** (за импорт в Excel / Google Sheets)
   - **DOCX** (официален Word документ с оформени таблици)
