E-Commerce Automation

Архитектура за паралелно E2E тестване на електронен магазин

Разработка на мащабируем автоматизиран тестов пакет за уеб платформа с над 10 000 артикула, използващ Playwright и TypeScript.

Технологии: Playwright, TypeScript, GitHub Actions, Docker
Контекст & Предизвикателство

Бавно изпълнение на регресионните тестове (над 45 минути) и висок брой фалшиви негативни резултати (flaky tests) поради динамично зареждащи се елементи в количката за пазаруване.

Решение & Стратегия

Имплементиране на Page Object Model (POM), изолация на тестовите състояния чрез API сесии и преструктуриране за паралелно изпълнение в 4 Docker контейнера в CI/CD тръбопровода.

6 мин Време за тест пакет (намалено от 45)
<1% Фалшиви аларми (Flakiness rate)
API & Load Testing

Тестване на сигурността и производителността на Финтех API

Имплементиране на непрекъснато тестване за RESTful API услуги на банкови транзакции.

Технологии: Postman, k6, Newman, Node.js, GitLab CI
Контекст & Предизвикателство

Необходимост от гаранция за нулева загуба на пакети и време за реакция под 200ms при симулиране на натоварване от 2000 едновременни потребители на критични банкови транзакционни точки.

Решение & Стратегия

Разработка на параметризирани k6 JS скриптове за натоварване, валидиране на JWT токени и автоматично стартиране на натоварващи тестове при всяко пускане на нова версия в GitLab CI.

180ms Средно време за отговор под товар
100% Успешни API заявки (HTTP 200 OK)

ТЕСТ ПЛАН: МОДУЛ "БАНКОВИ РАЗПЛАЩАНИЯ"

ID: TP-PAY-2026 • Версия 1.2
1. Обхват на тестването

Функционално, интеграционно и регресионно тестване на интеграцията на разплащателния портал (Stripe API) в E-Commerce уеб платформата.

2. Тест нива & Подходи
  • API Ниво: Позитивни/негативни тестове с невалидни данни за карти и лимити (Postman автоматизация).
  • UI Ниво: E2E сценарии за завършване на поръчка като гост и логнат потребител с 3D Secure верификация (Playwright).
3. Критерии за старт и край (Entry/Exit Criteria)
  • Старт: Готов билдинг в Dev среда, успешни Unit тестове (>80%), наличен пясъчник (sandbox) за плащания.
  • Край: 100% изпълнение на E2E тестовете, 0 критични (Blocker/Critical) дефекти, 100% успешно автоматизирано тестване на API.

ДЕФЕКТ: Срив на количката при бързо кликане на бутона "Поръчай"

CRITICAL • BUG-402
Описание:

При бързо двукратно натискане на бутона "Плащане" системата изпраща две паралелни POST заявки към `/api/checkout`, което води до двойно таксуване на клиента и грешка 500 от страна на сървъра.

Стъпки за възпроизвеждане:
  1. Добавете продукт в количката.
  2. Преминете към екрана за плащане.
  3. Кликнете върху бутона "Плащане" бързо два пъти последователно (double click).
Очакван резултат:

Бутонът да се деактивира след първия клик (disabled) и да се извърши еднократно плащане.

Реален резултат:

Бутонът остава активен. Сървърът обработва две заявки. Потребителят вижда екран "Грешка 500", а картата му е таксувана два пъти.
